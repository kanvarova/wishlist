# Статус проверки

Обновлено: 13 ноября 2026 года.

## Подтверждено локально

- TypeScript: проверка типов `tsc -b`.
- 22 автоматические проверки: бюджет, ближайшие цены, дорогие подарки, лимит шести, исключение недоступных, граница бюджета, безопасные URL; применение полной миграции в PostgreSQL/PGlite, нулевая начальная коллекция, RLS, анонимный/посторонний доступ, создание и атомарное редактирование со ссылками, откат недопустимых данных, порядок, приватность, дубликаты, отмена, неверные токены, покупка, защита сюрпризов, архив, настройки, каскадное удаление и ограничение частоты.
- Браузер: открытие домашней страницы по HTTP 200, исходное пустое состояние, открытие подбора, применение бюджета и типа, поиск, выбор сортировки и доступности, сброс, избранное без регистрации и экран подготовки `/admin` без настроек базы.
- Адаптивные размеры 1440, 768, 390 и 360 px проверяются в браузере на отсутствие горизонтального переполнения. Фактические устройства iPhone/Android не использовались.
- Локальный preview сначала собран нативным esbuild из-за Windows sandbox `spawn EPERM`. Затем **стандартная `pnpm build` успешно выполнена в [GitHub Actions](https://github.com/kanvarova/wishlist/actions/runs/43274773023) и в Vercel**. Production использует Vite. Подмена стандартной команды сборки в проекте не сделана.
- Production https://wishlist-kanvarova.vercel.app имеет состояние READY; анонимные HTTPS проверки `/`, `/admin`, gift-пути и `/og.png` получили 200, без редиректа на авторизацию Vercel. CSP и защитные HTTP-заголовки присутствуют. Браузер подтвердил пустое состояние, семь категорий из живой базы и отсутствие переполнения на ширине 390 px.
- Supabase: 0 товаров и броней при выпуске, 7 категорий, RLS на всех таблицах public. Учётная запись владельца подтверждена и внесена в список разрешений. Публичная регистрация выключена (`disable_signup: true`).

## Требует живых сервисов

**Обновление:** Supabase подключён, проект создан с согласия владельца, миграция применена к облаку. Реальные HTTPS запросы подтверждают пустой каталог и семь категорий; закрытые таблицы и административный save_gift отклоняют анонимные запросы с 401. Браузер загрузил категории и пустое состояние из живой базы. Подробности и оставшиеся настройки — в `DEPLOYMENT.md`.

Не подтверждены: успешный вход владельца с его паролем, загрузка/чтение фото через форму, операции управления из интерфейса через живой PostgREST, реальные параллельные HTTP бронирования с разных устройств, межбраузерное обновление резервирования и нативное меню отправки на телефоне. Для них не создавались фиктивные подарки в production и не запрашивался пароль владельца. Результаты PGlite проверяют SQL, а не весь облачный путь браузер → Auth → PostgREST → Storage.

Не загружайте тестовые подарки в production. Для полной приёмки используйте отдельный локальный Supabase или отдельный временный Free проект (учитывайте лимит активных проектов), затем оставьте production пустым.

## Приёмка после подключения

1. Открыть HTTPS URL в приватном окне без Vercel/GitHub login; проверить пустую коллекцию, русский интерфейс и отсутствие отсчёта без даты.
2. Войти в `/admin` владельцем; посторонний Supabase пользователь не должен иметь доступ. Попытки изменения анонимным REST запросом должны отклоняться.
3. В отдельной тестовой базе добавить подарок с фото и двумя магазинами. Перезагрузить страницу, отредактировать цену, описание и ссылки, проверить архив, категории, их скрытие и порядок. Затем проверить удаление.
4. На тестовых данных проверить примеры 5 500 / 7 000 / 9 500 ₸ при бюджете 10 000 ₸; затем 5 500 / 6 000 / 7 000 ₸ при бюджете 5 000 ₸. Комбинировать с категорией, поиском по магазину, типом и сортировкой.
5. Открыть два приватных браузера, одновременно забронировать один подарок. Успех должен получить только один; имя не должно появляться в публичных ответах и обычной панели.
6. Сохранить приватную ссылку, открыть её в другом браузере, отменить бронь; старая ссылка должна перестать работать. Новую бронь отметить купленной; повторная бронь и отмена покупки должны отклоняться.
7. Владелец не должен видеть выбранные подарки и имена в обычной панели. Открыть раздел сюрпризов: до подтверждения сетевого запроса раскрытия быть не должно. После подтверждения — проверить разрешённые детали, без токенов.
8. Проверить прямую `/gift/<uuid>`, WhatsApp/Telegram/Instagram, копирование, избранное после перезагрузки, клавиатуру и размеры телефонов. Проверить приложение при недоступной сети, запрещённом localStorage и выключенной анимации.
9. Проверить Production Deployment Protection, настройки Auth и публичные VITE переменные; обновить Site URL и повторить проверку внешнего URL без авторизации.
