# MY WISHLIST ♡ — личный вишлист Карины

Русскоязычный вишлист на React, TypeScript и Vite с Supabase Auth, PostgreSQL и Storage. Создан в существующем репозитории **https://github.com/kanvarova/wishlist**. Нового репозитория не требуется. Цена — в тенге. **В миграциях нет ни одного товара, цены или тестового подарка.** Начальная коллекция пуста.

## Возможности

- Редакционный дизайн в оливковой палитре; адаптивная сетка, клавиатурная навигация, системное уменьшение анимации.
- Живой бюджет: все доступные подарки в бюджете, ближе к выбранной сумме первыми. Если их нет — ближайшие более дорогие, до шести. Допуск начинается с 20% / 2 000 ₸ и расширяется при необходимости.
- Поиск по названию, описанию, категории и магазинам; категории, сортировка, доступность; подбор по бюджету и типу подарка, без случайного выбора и оценок желанности.
- Несколько магазинов на подарок; постоянная ссылка `/gift/<uuid>`; избранное в браузере; отправка системным меню либо копирование ссылки.
- Бронирование без регистрации. База создаёт уникальный случайный приватный токен, хранит только SHA-256. Приватная ссылка `/reservation#<token>` позволяет отменить бронь или подтвердить покупку. После подтверждения покупки отмена через эту ссылку закрыта.
- Приватная `/admin`: подарки, фото, магазины, архив, удаление, порядок, категории, цвета, тексты, настройки бюджета и необязательный отсчёт до дня рождения. Обычный экран не запрашивает статусы брони или имена гостей.
- Раздел «Раскрыть сюрпризы» делает отдельный привилегированный запрос только после явного подтверждения.

## Стек и структура

React 19, TypeScript, Vite, Lucide, обычный CSS без тяжёлого UI-фреймворка. CSS выбран вместо Tailwind, чтобы сохранить компактный набор зависимостей. Supabase JS обращается к PostgREST и защищённым SQL-функциям. Серверная бизнес-логика выполняется в PostgreSQL; service-role ключ в браузере не нужен.

```
src/App.tsx                  публичный сайт, подбор и приватная бронь
src/Admin.tsx                авторизация и управление
src/lib.ts                   клиент, алгоритм бюджета, обработка фото
src/styles.css               адаптивный дизайн
supabase/migrations/         схема, RLS, SQL-функции, пустые начальные данные
supabase/config.toml         локальная конфигурация (регистрация отключена)
tests/                      тесты бюджета и PostgreSQL в PGlite
vercel.json                 сборка, маршрутизация и защитные HTTP-заголовки
```

## Локальный запуск

Нужен Node.js 24 и pnpm 11.25.0 (либо npm). Репозиторий уже содержит lock-файл pnpm.

```sh
git clone https://github.com/kanvarova/wishlist.git
cd wishlist
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env.local
pnpm dev
```

В PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env.local`. Заполните две переменные из Supabase → Project Settings → API:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
```

Это публичные параметры клиента. **Никогда не помещайте service_role, secret key, пароль базы или пароль администратора в VITE_ переменные.** `.env*` исключены из Git, кроме пустого образца. При изменении окружения перезапустите Vite / пересоберите deployment.

Без настроенного Supabase сайт честно показывает состояние подготовки и пустую коллекцию. Вход и сохранение не имитируются. Это не подключённая рабочая база.

## Создание бесплатной базы Supabase

1. Создайте проект в организации на **Free**, без перехода на Pro и без платных дополнений. Пароль базы храните у себя.
2. В Supabase SQL Editor выполните содержимое `supabase/migrations/202611120001_wishlist.sql` **один раз в новом проекте**. Миграция создаёт семь редактируемых категорий и настройки; продуктов не создаёт. Для CLI: `supabase link --project-ref <ref>`, затем `supabase db push`.
3. В Authentication → Sign In / Providers отключите **Allow new users to sign up**. Локальная `config.toml` не меняет настройки облачного проекта: этот шаг обязателен и для него.
4. В Authentication → Users → Add user создайте **свою** учётную запись, задайте пароль и подтвердите email через административный интерфейс. Пароль не передавайте в Git или чат. Публичной формы регистрации в приложении нет.
5. Скопируйте UUID созданного пользователя и выполните в SQL Editor:

```sql
insert into public.admin_authorization(user_id)
values ('UUID-ВАШЕГО-ПОЛЬЗОВАТЕЛЯ');
```

6. В Authentication → URL Configuration установите окончательный HTTPS адрес как Site URL; локально допустим `http://localhost:5173`. Не добавляйте произвольные wildcard redirect URL.
7. Убедитесь, что bucket `gift-images` создан миграцией. Максимальный серверный размер — 5 МБ, форматы JPEG/PNG/WebP. Браузер принимает исходник до 10 МБ, уменьшает длинную сторону до 1600 px и кодирует WebP перед загрузкой. HEIC нужно предварительно экспортировать в JPG. Фото опубликованных и архивных товаров в этом публичном bucket доступны по известному URL — не загружайте личные документы.
8. Заполните публичные параметры в `.env.local` и Vercel. Проверьте вход через `/admin`.

## Публикация на Vercel Hobby за 0 ₸

1. Используйте личный **Hobby** аккаунт. Не включайте Pro, платные функции, сторонние платные интеграции или собственный домен.
2. В Vercel → Add New → Project импортируйте **kanvarova/wishlist**. При запросе GitHub выдайте Vercel доступ только к этому репозиторию. Framework: Vite; Node: 24; Build: `pnpm build`; Output: `dist`. `vercel.json` также задаёт эти настройки.
3. Добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в Production (и Preview, если нужны отдельные превью). Не добавляйте закрытые ключи.
4. Нажмите Deploy. Выберите доступное имя наподобие `wishlist-kanvarova`. Адрес назначается Vercel; желаемое имя не гарантировано.
5. Убедитесь, что **Production Deployment Protection** не требует входа в Vercel. Для этого публичного сайта отключайте её только на проекте wishlist; не меняйте защиту других проектов.
6. Откройте итоговый HTTPS URL без входа / в приватном окне телефона. Проверьте `/`, `/admin`, прямую `/gift/<id>` и `/reservation#<token>`. Настройте Site URL в Supabase на итоговый домен.
7. После пуша в main интеграция Vercel пересобирает сайт. Изменения подарков в панели пересборки не требуют.

Если доступы выдаются через Codex: подключите Supabase и Vercel; для Vercel дополнительно может потребоваться grant рабочему пространству по отдельной одноразовой ссылке. Для GitHub нужен push-доступ к существующему репозиторию, а для автоматического деплоя — GitHub App Vercel с доступом к нему. Доступ к одному сервису не даёт доступа к другим. Не присылайте закрытые ключи в чат.

## Первый настоящий подарок

Откройте `/admin`, войдите своей авторизованной учётной записью и нажмите «Добавить подарок». Укажите название, целую цену в ₸, категорию, описание, фото и при желании несколько магазинов со ссылками. Укажите тип для подбора. Оставьте «Опубликовать подарок» включённым, а «Убрать в архив» — выключенным. Нажмите «Сохранить подарок» и откройте «Посмотреть сайт». Товар сразу сохраняется в базе; другой открытый браузер обновляет каталог каждые 30 секунд и при возвращении на вкладку.

Стрелки в коллекции меняют порядок; при одинаковой цене он учитывается как дополнительный критерий. Основная выдача при активном бюджете по требованию ставит ближайшую к бюджету цену первой. Сортировка по цене / дате переопределяет ручной порядок.

Настройки → дата рождения не задана изначально, поэтому отсчёта нет. Дата используется для следующего ежегодного дня рождения по локальному времени посетителя. Вы можете поменять текст и выключить блок.

## Брони и безопасность

- RLS включён для всех таблиц. Публичный каталог содержит только опубликованные неархивные товары, ссылки и безопасный статус. Имена, таблица разрешённых администраторов, токены и throttling недоступны гостям.
- Создание брони сериализуется advisory lock, проверяет публикацию/архив, блокирует строку подарка и защищено UNIQUE(product_id). Два одновременных посетителя не могут занять один подарок.
- Приватный токен состоит из двух криптографически случайных UUID (около 244 бит случайности). В базе только SHA-256. Токен находится в URL fragment, поэтому не отправляется хостингу в HTTP пути или заголовке Referer. В браузере нет аналитики / сторонних скриптов. Ссылка предъявителя даёт управление бронью: не делитесь ею, обязательно сохраните после выбора.
- Утраченную ссылку восстановить без владельца нельзя; в базе токен тоже не хранится. Отмена удаляет бронь, старый токен перестаёт действовать. Повторное подтверждение покупки идемпотентно.
- Общее ограничение — 30 успешных броней за 10 минут; одному браузерному идентификатору — не чаще раза в 30 секунд. Отмена не сбрасывает лимит. Это базовое ограничение бесплатной личной системы, не полноценная антибот-защита: браузерный ID можно сменить, общий лимит можно исчерпать, массовые неуспешные запросы тоже потребляют API ресурсы. При публичной атаке требуется отдельная проверка наподобие Turnstile на Edge Function.
- «Сюрприз» защищает обычный интерфейс от случайного раскрытия. Владелец базы технически может самостоятельно прочитать SQL или открыть публичный сайт; это не криптографическое сокрытие от владельца инфраструктуры. Перед подтверждением панель не делает запрос на раскрытие.
- Архив снимает товар с публичного каталога; существующая бронь сохраняется. Удаление товара удаляет его магазины и бронь. Фото при замене/удалении может остаться в Storage: периодически удаляйте неиспользуемые файлы через Storage, учитывая квоту. Изображения намеренно не удаляются без проверки их использования.
- Для отзыва доступа администратора удалите его строку в `admin_authorization` через SQL Editor. RLS начнёт запрещать изменения сразу, независимо от открытой страницы.

## Проверки

```sh
pnpm test
pnpm build
```

Тесты PostgreSQL запускают **настоящий движок PostgreSQL в WASM (PGlite)**, создают отдельные макеты auth/storage схем и применяют полный SQL файл. Продукты существуют только в памяти теста, не в Supabase и не в миграциях. Проверяются RLS, анонимный/посторонний доступ, атомарное редактирование, недопустимые ссылки, хранение брони, дубликаты, неверные токены, отмена, покупка, архив, раскрытие и ограничение частоты. GitHub Actions запускает тесты и стандартную production-сборку.

Список проверок с текущими результатами и ограничениями — в `VERIFICATION.md`. Локальные тесты не заменяют проверку облачной авторизации, загрузки фото, одновременных HTTP запросов в живой Supabase и публичного HTTPS адреса после настройки аккаунтов.

## Частые проблемы

- **Пустой сайт с сообщением о подготовке:** не заданы публичные переменные Supabase; добавьте их и пересоберите.
- **Ошибка загрузки каталога:** проверьте, что проект не приостановлен, миграция выполнена, URL и ключ относятся к одному проекту. Не отключайте RLS для исправления.
- **Вход есть, управления нет:** UUID пользователя не внесён в `admin_authorization`. Создание пользователя само по себе не даёт прав.
- **Фото не загружается:** формат/размер, bucket, политика Storage, активность проекта и квота. HEIC не поддерживается напрямую.
- **Подарок не виден:** проверьте публикацию и архив, активные фильтры, категорию и бюджет. После изменения каталог обновится в течение 30 секунд; можно обновить страницу.
- **Приватная ссылка не работает:** она должна содержать `#` и весь токен. Отменённая или удалённая бронь не восстанавливается старой ссылкой. Не пересылайте ссылку через сервисы, которые её обрезают.
- **Публичный URL требует Vercel login:** проверьте Production Deployment Protection именно этого проекта и проверяйте production alias, а не защищённый preview.
- **В Windows sandbox возникает spawn EPERM:** среда запрещает дочерние процессы Vite/esbuild. Проверка типов и PostgreSQL тесты могут работать, но это не ошибка приложения. Стандартную сборку запускайте в обычном терминале или GitHub Actions / Vercel. Не отключайте системные защиты ради сборки.
- **Поделиться не открыло меню:** в неподдерживаемых браузерах копируется ссылка; clipboard требует HTTPS либо localhost. Если разрешение запрещено — скопируйте адрес вручную.
